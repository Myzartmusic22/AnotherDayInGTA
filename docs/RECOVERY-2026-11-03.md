## 2. Confirmed problems and root causes

### 2.1 RagePluginHook interface missing — the game was not launched through RPH

`asiloader.log` and `ScriptHookV.log` both show the last session starting at
**20:48** with `ScriptHookVDotNet-Loader.asi` and the other ASIs, and with **no
RagePluginHook** header for that session. `RagePluginHook.log` still ends at
**14:13**, i.e. RPH has not been started since. RPH is not an ASI: it only
injects when the game is started through `RagePluginHook.exe`. Starting from
Steam or `PlayGTAV.exe` gives exactly the reported symptoms — no RPH console and
no LSPDFR, because neither was ever loaded.

This is **not** an SHVDN v2/v3 conflict. Both are present and both are needed:
`ScriptHookVDotNet.log` shows `Persistence.dll` resolving to the v2 API, while
our plugin and EnableAllinteriors use v3. Removing either would break a script.

### 2.2 LSPDFR forced termination — corrupt character profile

`RagePluginHook.log` at 14:13 loads LSPDFR 0.4.9 successfully, then dies during
character selection:

```
CharacterSelected: 121 -> LSPDFR UNHANDLED EXCEPTION DURING GAME FIBER TICK
Exception: Rage.Plugins.InvalidHandleableException
         Operation is not valid because the specified Rage.PedInventory is invalid.
   at Rage.PedInventory.GiveNewWeapon(...)
   at WeaponSkin.ApplyToPed(...)
   at GamePlayer.cs:450 -> [FATAL] Forced termination
```

RPH then unloads LSPDFR, which is why LSPDFR looks "not recognized".

Evidence pinning the cause to the character save rather than to a mod:

* the 04:24 session loaded the same LSPDFR build and **did not** crash;
* `OFFICER ORLANDO.ls`/`.bak` were written at **05:04**, after that session;
* the 14:13 session is the first that loaded `OFFICER ORLANDO`;
* a `find -newermt` over `plugins/`, `lspdfr/` and the game root between 09:23
  and 14:14 shows **no** mod or config file changed — only our plugin backups
  and a mini crash report.

So the profile's saved weapon-skin list is being applied to a ped whose
inventory is not valid, and LSPDFR's own load path throws.

**Action taken (recoverable, nothing deleted):** both files were renamed in
place to `OFFICER ORLANDO.ls.disabled-20261103` / `.bak.disabled-20261103` and
copied into the backup folder, so LSPDFR falls back to a stock character. Restore
by renaming them back.

### 2.3 EnableAllinteriors failing to load

`ScriptHookVDotNet.log` repeats
`FileNotFoundException: LemonUI.SHVDN3, Version=2.0.0.0`. The assembly was only
in `plugins/`, which is RPH's folder; SHVDN resolves from `scripts/`. Copied to
`scripts/LemonUI.SHVDN3.dll` (original left in place).

### 2.4 SpeedLimitShower failing to load — not fixed

`MissingMethodException: GTA.UI.Notification.PostTicker` — the DLL was built
against an older SHVDN API than the installed v3 build. Only a rebuilt copy can
fix this; it is left disabled by its own failure and is unrelated to NPC AI.

### 2.5 NPCs not turning, not gesturing — three primaries fighting each other

`ConversationHold` re-issued `TASK_STAND_STILL`, `TASK_LOOK_AT_ENTITY` and
`TASK_TURN_PED_TO_FACE_ENTITY` together on every hold tick (1 s). Each
`TASK_STAND_STILL` cancels the turn that was issued a few lines earlier, so the
pedestrian stopped on the spot and rotated only by accident; repeated turn tasks
also restart the rotation. Rewritten so each native runs on its own clock and
the turn is issued only when `IS_PED_FACING_PED` says the ped is not facing the
player. Gestures are secondary upper-body tasks and are no longer cancelled.

### 2.6 Voice had no distance — fixed volume at the player's head

The live voice was a mono `WaveOutEvent` at a fixed gain, and queued lines were
attenuated once, at enqueue. Rewritten as described in section 4.

## 3. Standalone architecture (unchanged, verified)

`AnotherDay.Plugin` (SHVDN 3, `net48`) + `AnotherDay.Service` (`net10`) +
`AnotherDay.Shared` (`netstandard2.0`) reference **no** RPH, LSPDFR, Policing
Redefined, StopThePed or NPCI assembly. The NPCI reference needs LSPDFR/PR only
for duty state, personas, frisks and citations; none of that is used by the
conversation pipeline, which is SHVDN natives + NAudio + Gemini Live over a
local named pipe. The plugin therefore loads and works with RPH/LSPDFR installed
or absent, and simply coexists when they are running.

Reference-implemented behaviour (independent code, no binaries copied):
nearest-pedestrian selection, stand-still + look-at + body turn, facial talk
override from `mp_facial/mic_chatter`, vanilla gesture clips, streamed
dictionary loading before first use, and now distance/pan audio.

## 4. Spatial audio

`AnotherDay.Shared/AudioSpatial.cs` (pure, unit-tested):

* `Attenuation(distance, near, far)` — 1.0 inside `near` (default 3 m), gentle
  inverse-distance falloff, blended with smoothstep to a `MinimumGain` of 0.06
  exactly at `far` (default 45 m). No shelf, no discontinuity; changing distance
  by 0.25 m never moves the gain by more than 0.05.
* `Pan(lateralDot, distance)` — sign from the speaker's side, capped at ±0.8, and
  zero within arm's reach so a face-to-face talk is not panned.
* `StereoGains(pan, out l, out r)` — constant-power pan for handsets/headphones.
* `SmoothingState` — frame-rate-independent exponential approach with a 0.22 s
  constant and a 0.5 s cap on one frame, so a hitch cannot jump the volume.

`PcmPlayer` now runs `buffer -> mono-to-stereo (Left/RightVolume) -> volume ->
WaveOut`, and `AudioPlayback` does the same for pre-rendered lines (widening
mono files to stereo). `Main.SpatialFor()` resolves the speaker's position
against the camera each tick and feeds both players, so live conversations and
NPC-to-NPC lines share one curve. All playback stays sequential, so overlapping
conversations cannot stack gain.

New config keys (defaults in brackets): `spatialAudio` [true],
`audioNearDistanceMeters` [3], `audioFarDistanceMeters` [45]. Volume, master
gain and the service's own level multiply on top, so nothing can clip past 1.0.

## 7. Launch procedure

1. Start the game with `RagePluginHook.exe` (not Steam, not `PlayGTAV.exe`) so
   RPH and `plugins/LSPDFR/*` load.
2. Wait for the RPH console, then `LoadPlugin "LSPD First Response.dll"` if
   `startup.rphs` has not already done it.
3. Pick a stock character once in the LSPDFR character menu (the disabled
   `OFFICER ORLANDO` save is what crashed the load).
4. Story Mode with SHVDN is independent of the above; pressing **P** near a
   pedestrian starts the conversation.
5. Logs: `%LOCALAPPDATA%\AnotherDayInGTA\logs`, `RagePluginHook.log`,
   `ScriptHookVDotNet.log`.

If LSPDFR still force-terminates, send `RagePluginHook.log` from that session:
the character name and the exception line identify whether it is the same
`PedInventory` failure or a different plugin.
