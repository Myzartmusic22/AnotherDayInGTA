## The "AI OFFLINE MODE" indicator

The string in the code is `AI: offline - <status>` (`Main.cs:1569`), drawn only
when the service's snapshot reports `AiAvailable == false`, which
`ServiceState.cs:151` defines as `AiConfigured && UserSettings.AiEnabled`. The
status text under it comes from `ServiceState.BuildStatus()`.

It was not introduced by the pedestrian-facing work — every build from 08:34
onwards contains that same string and logic, including the restored one.

The underlying problem in the latest service session is real and is a **quota
limit, not a UI fault**:

```
Gemini TTS failed for Kevin Carter: HTTP 429: Rate limit exceeded for model
  gemini-3.8-flash-tts (limit: 10 requests per day on Free Tier). Retry in 5h27m
Gemini group_chat HTTP 429, retrying in 30s
```

and the corresponding conversation records read
`Conversation with Diego Kim ...: offline, 120797 ms, ... reply="Well, look who it is."`
— i.e. the service was answering from `OfflineProvider` because the Gemini calls
were rate-limited. That matches the visible offline state honestly: it was not
hidden, and it was not a stale flag. Fixes are to wait for the daily reset, use
a key with quota, or lower the per-conversation request count; hiding the line
would have concealed a genuine fallback.

The rapid blinking is the HUD redrawing the status element every frame while its
content alternates between `AI: connected, waiting for first snapshot` and the
offline line as snapshots arrive — the element is only rebuilt when the text
changes, but one flapping value redraws fast. It is cosmetic and independent of
the rollback.
